## 管理员配置：分组、上游账号与价格

### 0.5.5：异常处理、采购对账与重试

管理后台“视频任务”提供全部任务和异常处理入口，支持按账号、分组、供应商和异常类别筛选。异常包括自动处理超时、提交结果不明、重试耗尽、缺少用量、待用户结算、待采购对账和账号配置变化。一个任务可以同时属于多个类别，分类计数不能简单相加作为任务数。筛选会同时作用于任务列表和统计。

采购信息只对管理员可见。详情中分别展示用户实收、供应商接口报告金额、采购估算金额和已核对的实际扣费。没有金额代表未知；明确填写 `0` 才表示确认免费。估算金额由管理员录入，不从分组售价、倍率或用户扣费反推。LL2 未报告实际金额，须查询供应商账单后录入，不能直接把估算转为实际。

对账时填写估算金额或实际金额，以及说明；填写实际金额还必须提供供应商账单、订单或其他核对凭据的编号。金额按本站人民币余额口径录入，不自动换汇。编辑会保留操作者、时间、原值、新值和说明；并发编辑若版本过期会拒绝保存，刷新后核对。实际金额可清空，恢复为“待对账”；历史记录保留。错误任务也可能被供应商扣款，仍应核对。采购对账不会触发用户补扣、退款、修改使用日志或重写供应商报告金额。

毛利仅以已核对实际成本的任务为口径，包含同一筛选范围内失败任务的已确认成本。未核对的部分仍未知，不能用部分任务的毛利率代表整体利润。页面的 `$` 是历史额度符号，不代表自动换汇。

在“账号管理 → 新建/编辑视频账号 → 视频超时与重试”启用自定义策略。设置随账号保存，并在新任务接单时固定；修改账号配置不追溯改变已有任务。

升级前没有 `execution_policy` 快照的旧任务继续使用旧执行策略，不会因账号新增配置而突然停止。管理员对允许恢复的旧任务执行恢复时，会固定该供应商的默认策略，不读取账号当前自定义值；此后才受新的任务期限和有限重试控制。“缺少执行策略”与账单显示的 `legacy`（缺少计费快照）是两回事，缺少计费快照的任务仍不能自动追扣。

| 设置 | 默认值 | 允许范围 |
|---|---|---|
| 单次上游请求超时 | LL2 30 秒；Seedance 45 秒；Getoken 1200 秒 | 5–1200 秒 |
| 任务自动处理期限 | H3 1200 秒；Seedance 172800 秒 | 60–259200 秒 |
| 自动重试 | 开启 | 开启 / 关闭 |
| 最大重试次数 | 3 | 0–10 |
| 重试间隔 | 30 秒 | 5–3600 秒 |

最大重试次数指初次失败之后允许的追加尝试。正常返回“处理中”的查询不消耗重试次数，连续错误在成功响应后清零。网络错误、无效结果和缺少结算必需用量会受到有限重试控制。重试间隔是下限，后台恢复扫描和服务繁忙可能使实际间隔更长。计数和暂停状态存入数据库，重启不能重置预算。

单次请求超时同时适用于提交与查询，任务剩余期限更短时以任务期限为准。Getoken 的提交接口会等待生成结果，因此默认单次超时较长；同账号慢查询也可能等待该时长。两种供应商与内部结算各自独立恢复，避免一个供应商的慢请求阻塞另一供应商或用户账务恢复。同供应商待恢复任务按上次查询时间轮转，繁忙时不能保证每分钟查询到每个任务。

有限重试和暂停控制的是需要再次访问供应商的请求。已经取得完整计费依据的完成任务，即使上游执行处于暂停状态，内部幂等结算、使用日志补写和结算标记恢复仍可继续；它们不会重新生成视频，也不会重复扣用户主账。缺少必要用量时仍不能猜测数值结算。采购对账始终独立于这条用户扣费流程。

超时或重试耗尽后，任务保留原状态、供应商 ID 和额度预留，进入异常中心；这不表示供应商取消，也不表示已退款。管理员先核对上游，再点击恢复并填写原因，恢复原任务的查询与结算。正在执行上游请求时禁止重置；已结算、失败或已删除任务不能恢复。恢复操作有审计记录。

LL2 未拿到供应商 ID 时，只能在原有 24 小时上限内重发原始请求和同一幂等键；手动恢复不会延长该上限。Getoken、Seedance 的不明确创建结果不能安全重放，恢复按钮会拒绝；应先向供应商核对。已拿到 ID 的任务只查询原任务，不自动创建第二笔付费视频。采购对账不是供应商取消接口，也不解除待结算任务的额度预留。

本次数据库新增迁移 `345_video_task_operations.sql`：`video_tasks.execution_state`、采购记录表 `video_task_procurement`、操作审计表 `video_task_operations_audit`。不要求管理员手工改用户余额或补任务用量。部署关闭自动数据库初始化时，需要先按迁移机制应用该文件并登记校验和；应先备份并核验现有迁移。此说明仅用于管理员文档，不发布到客户使用指南。

本站按人民币充值与余额结算：充值人民币 1 元，页面显示 1 单位站内额度（沿用 `$1` 的展示方式），不做外汇换算。下文的本地秒价和 Token 售价都按站内额度配置。界面的 `$`、`$/MTok` 及代码中的 `usd` 字段是兼容命名，不能据此认定 LL2 按美元扣款；供应商采购成本须按其实际账单核对。

### 添加 Seedance 海外专用分组

1. 打开“分组管理 → 创建分组”。平台选择 **Seedance / BytePlus（OpenAI 兼容）** 预设，设置例如“Seedance 海外版”的名称。
2. 该预设底层保存为 OpenAI 兼容分组，自动开启媒体生成权限并选择 `usage_tokens`。这是协议归类，不表示会把视频请求发给 OpenAI 官方。
3. 检查媒体生成权限、分组倍率、用户额度/订阅规则以及允许模型。部分旧页面把媒体权限称为“允许图片生成”，它同时控制视频。
4. 在“分组逐模型定价 → 添加模型价格”中输入完整模型名，价格卡计费模式选择 **Token**；这里的价格卡模式 `token` 与上方视频策略 `usage_tokens` 是两个配合使用的配置项。“默认价格”界面标为 **$/MTok**，本站按 **站内额度/百万 Token** 填写，明确填写输出价；BytePlus 常规视频输入为 0，可明确设置输入价为 0。若用“渠道管理 → 模型定价”，还要把渠道关联到此分组。不要添加上下文区间价卡。模型别名与映射后的上游模型要能按定价规则正确命中；缺价时不应开放流量。
5. 如果业务要按秒出售，可显式改为 `local_price`，配置对应模型的分辨率秒价，并要求请求明确 `duration` 和 `resolution`。不要混用“每秒单价”和“每百万 Token 单价”。

也可编辑已有 OpenAI 或合成分组，显式配置媒体权限、Seedance 可用账号和计费方式。仅把分组名称改成“Seedance”不会自动赋予供应商权限。

### 添加 Seedance 海外上游账号

1. 打开“账号管理 → 添加账号”，选择 **Seedance / BytePlus** 快捷配置。
2. 账号采用 OpenAI 平台、API Key 类型。Base URL 预填 `https://ark.ap-southeast.bytepluses.com/api/v3`；如果使用其他已验证区域/兼容供应商，应填该供应商正确的 API Base。
3. 填入该 BytePlus 账号的供应商 API Key；这不是本站用户的调用 Key。确认供应商控制台已开通目标模型，有可用额度与配额。
4. 确认端点能力勾选 **Seedance / BytePlus**，即 `seedance`。普通对话账号不能仅因为同属 OpenAI 平台就自动承担视频任务。
5. 配置公开模型名到供应商模型 ID / `ep-*` 的映射。快捷配置列出的三个 1.0 模型是初始示例，按真实开通情况增删；不支持的模型不要留在可用列表。
6. 绑定刚创建的 Seedance 分组，设置合适的并发、账号状态、代理和额度规则，保存后回读确认能力与模型没有丢失。
7. 完成一次真实生成、下载和账务核对后再开放客户流量。没有真实 BytePlus 账号时可以验证协议与失败场景，但不能声称已验证供应商权限、真实输出质量或真实账单。

### 添加 MiniMax H3 分组与账号

1. 创建 MiniMax 视频分组，开启媒体生成权限。LL2 必须选择 **本地定价 `local_price`**，并明确配置对应模型/分辨率的秒价；不能选 `upstream_cost` 或 Seedance 专用的 `usage_tokens`。未配价格会拒绝接单，明确配置零价与缺价不同。
2. 在账号添加页选择 **MiniMax H3** 快捷配置。新账号默认选择 **LL2** 协议，Base URL 为 `https://api.ll2.cn`；平台为 OpenAI 兼容、类型为 API Key，勾选 `minimax_video` 能力并加入 `MiniMax-H3` 模型。客户端仍使用本站 `/v1/videos/generations`，不直接调用这个供应商地址。
3. 填入 LL2 供应商 Key，核实权限与余额；保持 `MiniMax-H3` → `MiniMax-H3` 模型映射，绑定正确分组，并设置并发与代理。不要给 LL2 账号设置按金额计算的账号配额：API 未报告实际采购金额，网关会拒绝启用此类配额的 LL2 账号；采购预算应在供应商控制台管理。用户余额、订阅和 API Key 配额仍按分组售价结算。自定义代理地址可以带路径前缀，需确认其转发 LL2 `/v2` 接口。普通 MiniMax 文本地址不能用作 H3 视频地址。
4. 768p / 768P 默认映射到 **720p 计费档**，输出仍是 768p。在分组配置 720p 秒价，或配置模型 `minimax-h3` 对应的 720p 秒价；模型级价格优先。核对独立视频倍率和用户分组倍率覆盖，避免以为页面上的普通分组倍率一定是最终倍率。
5. 保存并重新打开账号与分组，确认协议、能力、映射、价格和绑定均已保留。使用本站 Key 验收 5 秒 768P 请求，检查 `usage.output_seconds`、完整下载、任务账单、余额/订阅和使用日志；重复查询不得重复扣费。

#### 保留旧 Getoken 账号

`credentials.minimax_video_protocol` 明确区分 `ll2` 与 `getoken`。旧账号没有该字段或字段为空时继续使用 Getoken；不能根据域名猜协议。编辑旧账号的名称、分组或并发，不会自动转换协议。

建议保留旧 Getoken 账号，另外添加 LL2 账号。已有任务会绑定接单时的协议、规范化地址和凭证/自定义请求头指纹；修改原账号协议、地址或 Key 后，旧任务的恢复和查询可能暂停，恢复原配置后才能继续。切换前先等待原账号的任务完成并结算。主动切换协议会清空 Key，须输入所选供应商对应的新 Key；自定义代理路径不会被自动猜测或迁移。

Getoken 兼容账号仍填写其实际 Base URL 和 Key；只有该供应商确实返回美元成本且已核对成本与站内额度的计价口径时才可用 `upstream_cost`。LL2 只报告输出用量，不报告可用于成本结算的实际采购金额。

#### 秒价、1.2 倍率与成本口径

若把自己核实的人民币采购基准按本站规则填为 `p` 站内额度/秒，再配置有效倍率 `1.2`，则用户售价为 `p × 1.2` 站内额度/秒，费用为 `实际输出秒数 × p × 1.2` 站内额度。这是在基准上加价 20%；当基准确实等于采购成本且忽略其他费用时，对应售价口径毛利率约 16.67%，不是 20% 毛利率。

例如采购基准按人民币 **0.05 元/秒** 计算（实际以供应商账单为准），对应填写 **0.05 站内额度/秒**；倍率 `1.2` 后售价为 **0.06 站内额度/秒**，5 秒视频扣 **0.30 站内额度**，采购基准金额为人民币 **0.25 元**。此例只说明配置与算式，不确认 LL2 当前报价。需要 20% 毛利率时，且基准确实等于实际成本并忽略其他费用，倍率才是 `1 / (1 - 20%) = 1.25`。

本地配置价格只决定用户计费。LL2 接口报告的实际采购成本保持“未报告”，不能从配置秒价、用户扣款或倍率倒推实际采购成本，也不能用未知成本计算利润。管理员视频页可以分别录入采购估算和核对后的实际扣费，估算不会自动转成实际成本。缺失 `usage.output_seconds`、实际秒数与请求不一致或计费快照异常时，任务需在策略允许范围内继续查询，暂停后由管理员核对，不能猜测用量结算。

## 定价、审计与运维边界

- Seedance usage_tokens 只支持明确的平坦 Token 单价卡，阶梯价格卡拒绝接单；单位和模型映射必须核对。缺价不能按免费处理。
- 接单时保存计费策略。账号供应商成本、用户售价采用不同口径，未知成本不能推定为零，也不能据此计算利润。
- 并发与待结算额度存入持久任务。普通聊天/图片在 Redis 预留丢失后不会读取数据库视频预留；未知用量的估算也不是最终费用硬上限。完整限制见 VIDEO_OPERATIONS.md。
- 本地审核只处理文字和图片，不会解码音视频。输入支持不代表已完成音视频内容审核，供应商仍执行自身审核。
- 已知供应商任务 ID 只恢复查询。本站对 LL2 自动恢复创建设置接单后最多 24 小时的上限，恢复沿用原任务 ID 幂等键、原请求字节和原账号身份；这不是供应商承诺的幂等记录有效期。Getoken 和 Seedance 的不明确创建结果不能盲目重放。结算账本保证主扣费幂等，历史无快照任务不自动追扣。
- 任务中显示的 legacy 表示旧任务缺少新计费快照。下载历史记录不等于网关保存了视频文件副本。

## LL2 中断恢复与人工核对

提交前持久化请求和提交意图；创建响应丢失时，后台仅在任务执行策略和本站自动恢复窗口同时允许时重发完全相同的请求，仍使用原任务的幂等键。提交恢复窗口上限是接单后 24 小时；若任务保存了更早到期时间，以更早时间为准。账号策略的任务期限（H3 默认 20 分钟）、关闭重试或次数耗尽均可能更早暂停自动请求。这是本站的自动恢复限制，供应商未承诺幂等记录的保留时长，不能将其解释为供应商保证的 24 小时幂等有效期。保存供应商任务 ID 后只轮询状态，不重新创建；后台按分钟触发恢复扫描，不依赖客户继续轮询，也不保证每个任务恰好每分钟收到一次查询。

网络超时不证明供应商未接单，未知结果会保留额度预留。超过恢复窗口只停止自动提交，既不证明供应商已取消，也不应释放预留后重新生成；应核对原任务与供应商记录。已知供应商 ID 的查询不因 24 小时提交窗口结束而换用新任务。恢复时禁止更换幂等键、修改已保存请求、猜测供应商任务 ID，或为“解除卡住”直接改成失败/已结算。

核对时记录网关任务 ID、接单时间、绑定账号、协议、供应商任务 ID（若有）、最终状态、实际输出秒数及账本结果。确认供应商终态后再处理异常；不要把账号 Key、签名素材 URL 或供应商原始响应发布到客户文档。
